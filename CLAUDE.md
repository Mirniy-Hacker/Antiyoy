# CLAUDE.md

Мод игры Antiyoy (yiotro/Antiyoy, libGDX, Java). Переработка дипломатии,
экономики и ИИ. Некоммерческий проект — этого требует лицензия оригинала.

Читать перед работой: `docs/SPEC.md` (что делаем), `docs/ROADMAP.md`
(в каком порядке и как проверяем).

## Окружение

Разработка на Windows 11 + VS Code. Основной цикл — десктопная сборка
(`./gradlew lwjgl3:run`). iOS собирается только на macOS-раннере GitHub
Actions, вручную, и ставится на телефон через AltStore. Симулятора iOS на
Windows нет и не будет, это ограничение Apple, а не проекта.

## Структура

```
core/src/yio/tro/antiyoy/
  gameplay/                GameController, Province, Hex, FieldManager, LevelSnapshot
  gameplay/diplomacy/      DiplomacyManager, DiplomaticEntity, DiplomaticRelation,
                           DiplomaticContract, DiplomacyInfoCondensed
  gameplay/rules/GameRules флаги и настройки матча
  ai/                      AiFactory и реализации по уровням сложности
  menu/diplomatic_dialogs/ UI дипломатии
  menu/diplomatic_exchange/ UI обмена
  menu/scenes/             экраны меню
lwjgl3/   десктоп
ios/      MobiVM
assets/   ресурсы и языковые файлы
```

Новый код мода живёт в `gameplay/statehood/` (регионы, лояльность, бюджет,
отделение) и `gameplay/diplomacy/` (мнение, характеры, контракты).

## Жёсткие правила

1. **Сериализация.** Любое новое состояние обязано попадать в строку
   `DiplomacyInfoCondensed` и в `LevelSnapshot.diplomacyInfo`. Иначе оно
   обнулится при сохранении и при отмене хода. Префикс версии `v2/`,
   старые сейвы обязаны грузиться.
2. **Владелец не равен цвету.** После этапа 1 принадлежность гекса определяется
   `ownerId`, а `colorIndex` — только визуализация. Новых проверок вида
   `hex.colorIndex == other.colorIndex` в логике быть не должно.
3. **Флаги.** Каждая механика включается флагом в `GameRules`, раздельно для
   обычного режима и slay. Старое поведение остаётся доступным для сравнения.
4. **Константы.** Все числа только в `DiplomacyTuning`, `EconomyTuning`,
   `StatehoodTuning`. Магические числа в логике запрещены.
5. **Детерминизм.** Решения ИИ выводятся из состояния. Источник вариативности —
   черты характера и seed матча, а не `Math.random()` в момент решения.
6. **Производительность.** Расчёты по всем гексам — один раз за ход, с кэшем.
7. **Локализация.** Каждая новая строка UI заводится в языковых файлах в
   `assets`, иначе на экране появится сырой ключ.
8. **Мобильный UI.** Любое частое действие — не более трёх тапов с игрового
   поля. Проверять на телефоне, не на десктопе.

## Процесс

Этапы из ROADMAP выполняются по порядку. Каждый — своя ветка и PR. Следующий
не начинается, пока критерии приёмки предыдущего не выполнены на прогоне
100 автоматчей ИИ против ИИ.

Перед изменением незнакомого места сначала прочитать существующий код и
сказать, что именно собираешься менять. Движок старый, связи неочевидные.
