# План работ

Порядок жёсткий. Следующий этап не начинается, пока критерии приёмки
предыдущего не выполнены на прогоне 100 автоматчей.

---

## Этап 0. Инфраструктура

Без этого ничего не настроить.

1. Десктопная сборка запускается на Windows: `./gradlew lwjgl3:run`.
2. IPA собирается на GitHub Actions и ставится на телефон через AltStore.
   **Проверять на неизменённой игре.** Если порт не заводится, узнать это
   надо сейчас, а не через месяц работы.
3. Режим автоматчей: `--sim N --seed S` — N партий ИИ против ИИ без отрисовки,
   на выходе CSV: победитель, число ходов, максимальная казна каждого, число
   объявлений войны, число сделок, доля карты у лидера по ходам, число
   отделившихся регионов.
4. Классы `DiplomacyTuning`, `EconomyTuning`, `StatehoodTuning`.
5. Флаги в `GameRules`, раздельно для обычного режима и slay.
6. Версионная сериализация `v2/`: пока пустая, но с рабочим загрузчиком
   старых сейвов.

**Приёмка:** 100 автоматчей проходят за разумное время, CSV осмысленный,
старые сохранения грузятся, IPA стоит на телефоне.

### Workflow для IPA

Положить в `.github/workflows/ios.yml`. Репозиторий должен быть публичным:
на публичных репозиториях macOS-раннеры бесплатны без лимита минут.

```yaml
name: Build iOS IPA

on:
  workflow_dispatch:

jobs:
  build:
    runs-on: macos-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-java@v4
        with:
          distribution: temurin
          java-version: '17'

      - run: xcodebuild -version
      - run: chmod +x ./gradlew

      # TODO при первом запуске проверить:
      #   точное имя задачи (./gradlew :ios:tasks)
      #   работает ли robovm.iosSkipSigning в текущей версии MobiVM
      #   при жалобах на версию iOS SDK — зафиксировать Xcode через
      #   maxim-lobanov/setup-xcode
      - name: Build unsigned IPA
        run: ./gradlew :ios:createIPA -Probovm.iosSkipSigning=true --stacktrace

      - name: Locate artifact
        run: find ios/build -name "*.ipa" -o -name "*.app" | head -50

      - uses: actions/upload-artifact@v4
        with:
          name: antiyoy-mod-ipa
          path: |
            ios/build/robovm/*.ipa
            ios/build/**/*.ipa
          if-no-files-found: error
          retention-days: 14
```

## Этап 1. Владелец против цвета

Чистый рефакторинг, ноль изменений в поведении. Спека, часть I.

- `entityId` в `DiplomaticEntity`, `ownerId` в `Hex`
- Отношения и контракты ключуются по `entityId`
- Все проверки принадлежности переведены с цвета на `ownerId`
- Расширенная палитра и штриховка для совпадающих цветов

**Приёмка:** автоматчи с тем же seed до и после рефакторинга дают **идентичные**
результаты. Реплеи старых партий воспроизводятся без расхождений.

Этот этап делается до всего остального. Потом он станет вдвое дороже.

## Этап 2. Экономика

Спека, часть II.

- Потолок казны `20 × income`, утечка 10%/ход
- Удорожание найма +15% за юнит внутри хода

**Приёмка:** медианная длительность партии на большой карте выросла минимум в
полтора раза, максимальная казна лидера упала минимум вдвое, доля партий,
заканчивающихся блицем после накопления, стремится к нулю.

## Этап 3. Интерфейс, база

Делается рано: дальше придётся много играть руками для настройки.
Спека, часть IX.

- Липкий режим постройки
- Долгий тап → контекстное меню с ценами
- Автопостройка ферм до порога

**Приёмка:** постройка 10 ферм подряд требует 11 тапов вместо 30+. Проверяется
на телефоне.

## Этап 4. Регионы и лояльность

Спека, часть III, разделы 3.1–3.3. Крупный этап, три подхода.

4a. Нарезка на регионы, `loyalty`, влияние на доход, тон гекса, сериализация.
4b. Карточка региона: число, разбивка причин, приоритет, разовая выплата.
4c. Политика провинции, автораспределение, эвристика ИИ.

**Приёмка:** выкуп половины карты за один ход приводит к падению лояльности
ниже 40 минимум в половине купленных регионов в течение 6 ходов. ИИ не теряет
лояльность в штатной ситуации. Отмена хода восстанавливает лояльность,
приоритеты и политику.

---

## Этап 5. Отделение и новые государства

Спека, часть III, разделы 3.4–3.8. Возможен только после этапов 1 и 4.

- Волнения, отделение, создание новой сущности
- Формирование характера из родителя, причины, соседей и размера
- Стартовые отношения, обида основания
- Признание независимости как тип контракта
- Поведение ИИ при потере и при появлении сепаратистов

**Приёмка:** в автоматчах появляются отделившиеся государства, они не
вымирают мгновенно и не ломают подсчёт победителя. Два государства,
отделившиеся по разным причинам, статистически различаются по числу
объявлений войны и по числу принятых сделок.

## Этап 6. Ядро дипломатии

Спека, часть IV.

- `opinion`, `trust`, модификаторы с затуханием
- Сила, ненависть к лидеру
- Репутация
- Пороги решений вместо рандома
- Разбивка причин в `DipInfoDialog`

**Приёмка:** в логе автоматча каждое объявление войны объясняется состоянием
мнения и соотношением сил, решений по рандому нет ни одного. Лидер по силе
получает враждебность минимум трёх сущностей к 40-му ходу.

Спека, часть VI.

## Этап 9. Дипломатические действия

Спека, часть VII. Единый экран дипломатии делается **до** добавления действий,
иначе каждое новое утонет во вложенных диалогах.

Порядок: ультиматум, пакт о ненападении, подкуп, дань, ДМЗ-граница, коалиция.
Признание независимости уже сделано на этапе 5.

**Приёмка:** любое действие доступно не более чем в три тапа с игрового поля.
